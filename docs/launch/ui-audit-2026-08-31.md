## Cohérence de la copie (vs. brief du 31 août)

- **Terme pivot.** Le site dit « dépendances numériques » / « indépendance numérique » ; « souveraineté numérique » n'apparaît que dans `meta keywords` et une question FAQ. Le brief veut la souveraineté comme résultat. Décision à prendre : souveraineté = objectif, indépendance = chemin.
- **Offre propre absente.** Aucune section « ce que nous faisons » (conseil, accompagnement). Aucune mention de la plateforme d'agents IA (grep : 0 occurrence). L'à-propos mentionne « conseil » dans « comment le site est financé » seulement.
- **Partenaires.** Disclosure présente (`/page/transparence-partenariats`, cas AIFEL). Absent : « le partenaire est choisi pour l'adéquation au cas d'usage, pas pour le partenariat » sur l'accueil ; absent partout : « les partenaires participent au financement / subvention du projet ».
- **Écosystème américain.** Nommé une fois (« outils américains », `/page/independance-numerique`) et dans une FAQ. Le hero ne dit pas de quoi on sort.
- **Une chose, cinq noms.** Nav « Décrire mon besoin » → page « Demande de cadrage » → H1 « Décrire vos dépendances » → footer « Diagnostic » → section « Formulaire de cadrage ». → Un seul nom : Diagnostic.
- **Texte de chantier public.** `/page/confidentialite` : « À compléter avant ouverture publique », « Version de travail ». Blocant.
- Lexique IA : faible. Phrases courtes, vouvoiement stable, dates de revue présentes. Quelques parallélismes négatifs (« pas de drapeau », « sans déplacer le risque ailleurs ») — acceptables.

## Formulaires

Trois formulaires différents pour une même file :

| Emplacement | Champs | Obligatoires |
|---|---|---|
| Accueil `#contact` | 12 `input type=text` (dont « Message » sur une ligne, « Budget », « Effectif », « Secteur » en texte libre) | nom, e-mail, **téléphone** |
| `/page/contact` | mêmes 12 | idem |
| `/page/diagnostic-souverainete` | nom, e-mail, organisation, fonction, textarea | nom, e-mail, organisation, message |

Le backend (`submit.php`, `lead-form.20260827.js`) sérialise tout champ présent, gère le consentement nominatif (`aifel` / `provider-intro-v1`) et la file chiffrée : un formulaire multi-étapes n'exige pas de refonte, seulement (a) une sauvegarde partielle à l'étape 1 et (b) des champs structurés.

### Proposition — un composant, trois étapes

- **Étape 1 — contact (sauvegardée immédiatement, sert au remarketing)** : e-mail professionnel, nom, organisation, fonction (select : DSI · RSSI · CTO · DG/DGS · achats · transformation · autre).
- **Étape 2 — qualification** (champs du spec §10) : type d'organisation (PME · ETI · grand compte · collectivité · établissement public · santé · autre) ; effectif (tranches) ; outils en place (cases : Microsoft 365 · Teams · Google Workspace · Zoom · AWS · Azure · GCP · autre) ; cas d'usage examinés (visio/collab · messagerie · bureautique · identité · hébergement · sauvegarde · IA/agents · autre) ; contraintes (données sensibles/RGPD · HDS · NIS2 · SecNumCloud · commande publique) ; déclencheur (renouvellement · incident · audit · programme cloud · exigence de tutelle) ; échéance (< 3 mois · 3–6 · 6–12 · > 12) ; budget indicatif (tranches, facultatif) ; **intérêt pour un financement ou une subvention via partenaires** (oui/non).
- **Étape 3 — suite souhaitée** : résultat indépendant seul · échange de 30 min · accompagnement · mise en relation nominative (fait apparaître la case de consentement partenaire) ; message libre ; téléphone (facultatif).
